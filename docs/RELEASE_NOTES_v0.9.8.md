**Please note:** this release has had only limited testing: automated checks and one Android phone. The new way pictures are drawn and shown (on a thread of their own) has not been tried on a Windows, Linux or Mac computer, nor on any phone but that one. If something looks, plays or runs wrong, keep the previous version and send the game's report file (the newest file in the `logs` folder that starts with `report-`, or `ico-pc.log`) with a short description of what you saw.

## New

- Options > Gameplay > Yorda trips: running hand in hand for three seconds makes Yorda fall, as she does after the main gate opens. Off unless you turn it on.
- Options > Gameplay > Second memory card: ten more save slots on a second card; the game's own save and load screens offer both cards.
- Options > Extras > Back up your data and Restore from a backup, on the title screen (Windows, Linux, the Steam Deck, Mac and Android): your memory card, save states, settings and achievements in one `.zip` file you choose where to save, and put back from such a file, to keep a copy, move to another computer or phone, or go back to an earlier point. On Android this works even where the game's folder is hidden (Android 13 and later).
- Options > Language > Русский (bob-ttz): the subtitles and the game's menus in Russian, translated by bob-ttz. The game plays its English version underneath, so saves work with every language. Menu language also offers it.
- Options > Language > Русский (cobra838): a second Russian translation of the subtitles and menus, by cobra838. It works the same way as bob-ttz's, and Menu language offers it too.
- The ending's credits now also name the translators, the contributors and the special thanks.
- On Windows and Android, save states now carry over to later versions when the part of the game they were saved in has not changed. When it has, loading the state tells you which version made it and why it cannot be resumed, instead of only saying it is from another version. A gameplay setting that a later version adds does not stop a state from carrying over while you leave that setting as it starts. Save states made by v0.9.7 or earlier cannot carry over.
- On a keyboard, F6 opens the Save states page. During play it pauses the game first, and pressed again on the page it takes you back to the game.
- The pictures are now drawn and shown on a thread of their own, so the game goes on with its next step while a picture is sent to the screen. The game still waits while a picture reads what that step changes, so the gain is smaller than a whole picture, and there is none at Frame rate Original. On phones it takes some of the work that held the sound back during play off the game, and can raise the frame rate where the graphics chip has time to spare. If a computer or phone shows problems with it, `render_thread = off` in the `[dev]` part of the settings file puts everything back on one thread.
- The game no longer repeats graphics commands that change nothing, so each picture takes less processor work with every Graphics API choice; `bind_cache = false` in the `[dev]` part of the settings file turns this off if a device shows problems with it.
- With Graphics API set to Direct3D 11, the game's 3D models are now prepared once per frame, as with the other Graphics API choices, so older graphics cards spend less time on each picture.
- At high resolutions (on phones at Resolution Auto or 2x), the pause menu's and the Options pages' words are drawn from letters prepared once instead of being worked out again for every pixel of every picture, so the menus take less of the graphics chip's time. They look exactly as before.
- On phones, the glowing outline around Yorda and the shadows (the aura) is worked out in two shorter steps instead of one long one per pixel, which takes less of the graphics chip's time; the picture is the same.
- On phones, the step that works out Yorda's and Ico's shadows reads less per pixel and no longer makes the graphics chip load and save a full-size picture that nothing looks at, so it takes less of the graphics chip's time; the picture is the same.
- On phones, a picture step that draws into only a part of the screen now has the graphics chip load and save only that part; the picture is the same. Most steps during play cover the whole screen, and those stay as they were.
- Every picture now skips a few steps that drew or saved nothing anyone looked at, which saves graphics time on phones; the picture is the same.
- On graphics chips that can read the picture while drawing it (such as Adreno chips with the open Turnip driver, and many Mali chips), the game prepares several times fewer graphics pipelines at its first start and blends colours exactly as the PlayStation 2 did. Other chips, including PowerVR and Adreno with Qualcomm's own driver, draw as before.

## Fixed

- The game kept writing the depth of every picture back to memory for the whole session after its first frame, which cost graphics time every picture, most of all on phones; it now does so only while a frame needs it. The setting that hands the picture's depth to an effects program such as ReShade, on unless you turn it off, also kept it doing so on every phone and on computers without such a program; it now does only while such a program is running.
- On Android, a save state made in an earlier session could not be loaded (the game closed). Save states made before you closed the app now load after you open it again.
- A save state's picture showed the pause menu and was small. It now shows the game as it was when you paused, larger and in its own shape, without the menu. A state saved right after loading another one gets the loaded state's picture.
- A wall could be seen through for an instant when the camera moved past it (with Frame rate above Original). The frames shown between the game's own frames no longer take the camera through a wall or a floor.
- Walking into the next area, the walls of the room you were leaving could change to the next area's look for an instant before the screen faded. The room now keeps its own look until the fade.
- On phones with a lot of memory, preparing the graphics at the first start stopped early, and the game then stuttered during play while it prepared the rest. It now finishes behind the progress bar before the game starts.
- With anti-aliasing, Downsampling, or a Resolution larger than the window, the game could stutter once when it first showed a picture; what it needs for that is now prepared at the first start with the rest of the graphics.
- From this version on, an update that does not change how the game draws keeps the graphics prepared before it, so its first start no longer prepares them all again. The first start of this version still prepares them once.
- Entering a new area, or loading a save, could make the game hitch for a second while the new area's pictures were prepared: an extra picture shown between two of the game's frames made the game wait for it. The game now leaves such an extra picture out when it would hold up the game, so the game keeps its pace; every frame of the game is still shown.
