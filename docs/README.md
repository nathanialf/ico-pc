# docs/

An index of this directory: what each file is for.

| file | what it is |
| --- | --- |
| [`BUILDING.md`](BUILDING.md) | the full build: host packages, what `./build.sh`, `tools/setup.sh` and each build step do, the hooks, the dashboard, running the ELF in a PS2 emulator |
| [`LEGAL.md`](LEGAL.md) | what the repository may and may not contain, why the data tables are generated from the user's ELF at build time, and which references were used. Read it before contributing |
| [`HEADERS.md`](HEADERS.md) | which headers the disc attests, the code includes, where the other declarations live, and the derived-name tokens |
| [`PORT.md`](PORT.md) | how the PC port ([ico-pc](https://github.com/nathanialf/ico-pc)) relates to this repository: the host branches in `ico2/` and `sce/`, what flows upstream, what stays in the port, how it merges `main` |
| [`PROGRAMMERS.md`](PROGRAMMERS.md) | the `ico2/` directories, what each holds, and who wrote them |
| [`PROGRESS.md`](PROGRESS.md) | the per-section table of how much of the ELF is identical to the base, split into the share built from source and the share from the data tables. Generated by `tools/check_elf.py --progress` |
| `index.html`, `progress.json` | the progress dashboard and its data. `progress.json` is generated by `tools/check_elf.py --progress`; `.github/scripts/build_pages_site.sh` publishes these two and `PROGRESS.md` to GitHub Pages, and nothing else from this directory |

`tools/README.md` describes every tool.

## Local files that are not part of the repository

A maintainer's checkout may also hold `NOTES.md`, `COOKBOOK.md`,
`MATCH_VU.md`, `MATCHING_NOTES.md`, `ARCHIVE_retired_notes.md` and
`pal_source_tree.{md,json}` here: notes on the compiler's and assembler's
behaviour and a census of the disc's listing. They are gitignored, nothing
in the build reads them, and nothing in the repository depends on them.
