## Fixed

- On Android, save states made from this version on can carry over to later versions of the game, as they do on Windows (a later version still refuses one when it changed the part of the game it was saved in): until now every save state on Android could only be resumed by the exact version that made it, because it held places of texts inside the game that the game could not name. Save states made by v0.11.7 and v0.11.8 on Android now resume where they were saved in this version too, unless the part of the game they were saved in changed. On every system, a save state made while a long message (such as a Japanese one) was in use no longer keeps an out-of-date place for it, and when a save state cannot carry over, the log lists what in it could not be named.
- Every other save state made by an older version of the game, or on another kind of device, no longer ends in "cannot be loaded": when the game cannot resume it where it was saved, Load continues from the last checkpoint the state holds (the place a game over would have taken you back to), as Continue does with a memory card save, with the state's play time and difficulty. The Save states page and a message say so, and nothing is written to your memory card. Only a state saved in a new game before its first checkpoint has nothing to continue from, and the message says that.
- On iPhone and iPad, loading a save state after the game had been closed and opened again could damage the game in memory and make it close a moment later. Such a load now continues from the state's last checkpoint instead; loading a state in the same session still resumes exactly where it was saved. On Mac, save states made from this version on resume exactly in a later session too, and older Mac save states continue from their last checkpoint.
- On Windows, a save state carried over from an earlier version no longer has a few of the game's own numbers (such as animation values) slightly changed when it loads.
- A save state is no longer refused with "settings differ" just because a setting was written down at its default value after the state was made (for example after the Debug menu was opened once).
