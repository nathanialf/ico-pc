## Fixed

- On Android, save states made from this version on can carry over to later versions of the game, as they do on Windows (a later version still refuses one when it changed the part of the game it was saved in): until now every save state on Android could only be resumed by the exact version that made it, because it held places of texts inside the game that the game could not name. A save state made by v0.11.7 or v0.11.8 on Android resumes where it was saved in this version when the game can be sure it resumes it exactly; otherwise it continues from its last checkpoint, as below. On every system, a save state made while a long message (such as a Japanese one) was in use no longer keeps an out-of-date place for it, and when a save state cannot carry over, the log lists what in it could not be named.
- A save state made by an older version of the game, or on another kind of device, that the game cannot resume where it was saved no longer ends in "cannot be loaded": Load continues from the last checkpoint the state holds (the place a game over would have taken you back to), as Continue does with a memory card save, with the state's difficulty, and with its play time when the game can find it in the state. The Save states page and a message say so, and nothing is written to your memory card. This Load works from the pause menu and the title screen; pressing F9 during play asks you to pause first. A state saved from another disc or on a Permadeath journey is still refused, and so is one with no checkpoint to continue from (saved in a new game before its first checkpoint, or one where the game cannot find it); the message says which.
