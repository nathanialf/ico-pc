## New

- When the game closes by itself without a message, the next start now records where it was and how much memory the device had left, in the log and in the new `last-run.txt` file in the logs folder (report zips include it), so the cause can be found from one report.
- On Android 11 and later, the log and the report file now say how Android ended the game the time before (for example, low on memory, stopped responding, or closed from the recent apps list), with the system's own crash details when it kept them.
- On Android and Linux, the log now also says what is using the device's memory while the game prepares its graphics at start, every ten seconds, and when the system warns that memory is low, so a report shows why a device ran out of memory.

## Fixed

- On devices whose graphics driver keeps memory for every effect it prepares (such as Adreno graphics on Qualcomm's own driver), the game now measures at each start how much memory each prepared effect takes and stops preparing them while enough memory is left to play, preparing the rest when they are first needed, instead of filling the memory before the game begins.
- On phones whose graphics draw some see-through surfaces in two steps (such as Mali graphics), surfaces that can be drawn in one step with the same picture now are, which takes some work off each picture; the game checks at start that the picture comes out the same and keeps the old way if it does not.
- On tablets, phones and handhelds with Adreno graphics on Qualcomm's own driver, v0.11.7's request to run the game's graphics work ahead of other apps is withdrawn: it did not reduce the freezes and may have slowed the rest of the device.
- Characters' shadows above the original resolution, which made v0.11.7 slower than v0.11.6 on tablets at higher resolutions, now skip a step of graphics work that was only needed to read the shadow back: at the first shadow it draws, the game checks on your device that the quicker ways of drawing them give exactly the same picture and uses one of them, the quickest where the device can time them (if the check finds any difference, shadows are drawn as in v0.11.7).
- Logs for bug reports now judge slow moments against the frame rate the game is running at (on the European release nearly every frame was reported slow), and one of the automatic captures of a slow moment is kept for gameplay instead of all of them being used up in the opening.
- On phones, tablets and handhelds with the Adreno 740 chip on Qualcomm's own graphics driver, and on any Adreno chip with the open Turnip driver, pieces of walls and floors near the edge of the picture or close to the camera could vanish; they are now drawn as on other devices.
- While the game is paused and on the title screen, on devices where it gives exactly the same picture, the scene behind the menu is drawn once and then kept, instead of being drawn again for every picture, which takes most of the graphics work off the menu screens; the game checks the first kept picture against a fully drawn one and draws every picture in full if they differ (Vulkan only).
