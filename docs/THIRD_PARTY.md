# Third-party code and tools

What the PC port builds against, links or runs at build/test time, with the pinned version, licence
and where it comes from. Licence policy: nothing GPL is linked or shipped (GPL build tools run on
the build host only); everything statically linked into the MIT program must be MIT-compatible and
its notice must ship with the binary. A new dependency gets a row here and an entry in
`tools/notices/manifest.json` in the same change.

Pins live in the fetch scripts, and the Mac's DXC pin in
`.github/workflows/ios.yml`; changing a version means changing the pin
(version and SHA-256 or commit) there and the row here.

`--arch {x64,arm64}`, which picks the entries limited to one architecture)
writes it from `tools/notices/manifest.json`:
one entry per component (name, version, licence, use, and where its licence
text is: a vendored file, a fetched dependency's file under
`tools/toolchain/deps/`, or the notice comment of a file in the tree), and it
fails if any text is missing. A component added to the tables above gets a
manifest entry in the same change.

The Vulkan loader and the GPU driver are the player's system components and
are not shipped; neither is a driver package a player adds on Android
(the app only loads what the player chose).
