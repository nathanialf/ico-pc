# config/link_order.jun26.txt: the objects of the Jun-26-2001 demo link, one per line, in link order.
#
# The demo directory (CUS97113 on the Official U.S. PlayStation Magazine's
# disc SCUS-97158, issue 49) ships no map or listing. This order is PAL's
# (config/link_order.pal.txt on main, MAIN.MAP's object order) carried over by
# the function census, tools/correlate_elf.py, run against the PAL build and
# against the Aug-6-2001 prototype's build (the aug6 branch, whose names come
# from that disc's TRFILE.TXT): each object keeps its place while its .text
# twins in the demo ELF keep the same relative order. A line that departs
# from PAL's order says why in a comment on the line. Every output section of
# config/link.jun26.ld takes its inputs in this one order. tools/gen_ninja.py
# reads this file and fails on any tracked .c/.s/.dsm under ico2/ or sce/
# that is missing here, and on any listed file that does not exist.
# tools/ico_version.{py,sh} detect the target (jun26) by this file's
# existence.
#
# Line forms:
#   <path>             a source file (.c compiled by tools/compile_c.sh, .s
#                      assembled per archive, ico2/vusrc/*.dsm by dvp-as)
#   data:<member>      a data-only ico2000.a member: every row of
#                      config/data_members.jun26.txt for it, generated from
#                      the user's base ELF at build time by
#                      tools/gen_data_c.py from the record types
#                      config/data_schema.jun26.txt names.
#
# Tokens after a path:
#   align.<sec>=16     the ROM starts this object's <sec> (data or rodata)
#                      16-aligned after fill that its own section alignment
#                      does not produce. While any line carries one,
#                      tools/gen_ninja.py lists that output section input by
#                      input (build/<sec>.inputs.ld, which the script
#                      INCLUDEs) with an ALIGN before the object; otherwise
#                      the file is empty and the script's wildcards alone
#                      place the section.
#   overlay-fill=N     on a .dsm line: the byte, decimal 0 to 255, that
#                      dvp-as repeats over the program's constant-address
#                      overlay section (--overlay-fill=N, from
#                      tools/binutils-dvp-overlay-fill.patch). It is the
#                      period assembler's uninitialised heap memory, measured
#                      on the disc's ELF, not a feature of the source. The
#                      demo ELF holds 0x6E (110) in all five, as the JPN, USA
#                      and Aug-6-2001 ELFs do; the seven continuation
#                      overlays are zero.
#
# Absent from the demo, as from the Aug-6-2001 prototype: puddle.c,
# waterDot.c, windmill.c, sce/libcdvd/libcdvd_267388.c and
# sce/libscf/libscf.c (no function of them is found in the demo ELF).
# Absent from the demo though the prototype has them (its TRFILE.TXT
# lists their functions): clipCollisionManager.c, flyManager.c,
# waySystemManager.c and itou_gflag.c. No function of theirs is found in
# the demo ELF and nothing in the demo calls one, so no object of them is
# linked.
