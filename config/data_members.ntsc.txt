# config/data_members.ntsc.txt -- the ICO USA retail ELF's data-only ico2000.a members.
#
# One row per (member, section) for the members of
# config/data_members.pal.txt that this ELF holds: the 70 members MAIN.MAP
# lists with .data/.rodata/.sdata but no .text, plus the unmapped runs (member
# name unmapped_<VMA>, the VMA being PAL's, kept as the member's name). Two of
# PAL's rows have none here, hintTable (unmapped_002ADBA0) and jimakuFileName
# (unmapped_0055FBD0): this build has neither table nor any code that reads
# one (the group comments below say where each would sit). Each member, typed
# by config/data_schema.ntsc.txt, is written as one C translation unit by
# tools/gen_data_c.py (build/data/<member>.c, its rows the sections of that
# one object), which reads this table and the user's own
# baserom/ntsc/baseelf.elf; the bytes are never committed.
#
# Columns: <section> <member> <rom_lo> <rom_hi> <symbol>@<offset>,...
#   section   the section the bytes occupy in the retail ELF
#   rom_lo/hi VMA range [lo, hi) in baserom/ntsc/baseelf.elf (rom offset + 0x100000)
#   symbols   the PAL member's names (MAIN.MAP's, or the derived name its C
#             reader uses), offset from rom_lo
#
# Derivation. The USA disc ships no map or listing, and MAIN.MAP is a
# different, later link: no address below comes from either. The names are
# PAL's, carried by member order. Every start was found in this ELF:
#   1. Code. Each function the census (tools/correlate_elf.py) pairs with a
#      PAL function of the same length loads the same data the same way, so
#      a %hi/%lo pair or a $gp offset in the PAL function and the same
#      instruction in the twin give the PAL address and this ELF's address of
#      one datum. Where PAL's reader has no twin here, its USA counterpart is
#      the function config/stubs.ntsc.txt names after it (a body equal with
#      immediates masked, or PAL's size and order); a member's base is pinned
#      only when that function reads it. Every member's base read by code
#      ("code:", the readers common to both builds) is pinned this way, and
#      so is the .data, .rodata or .sdata of each code-owning neighbour.
#   2. Neighbours. Each run lies between two code-owning objects whose
#      sections are pinned by step 1; the group comments name them. A
#      member no code reads is bounded by the pinned members on each side.
#   3. Content. Each row was decoded with PAL's record type
#      (config/data_schema.pal.txt) and compared with PAL's member record by
#      record, pointer words compared as the address the PAL target has in
#      this link (functions by the census, data by step 1), strings by
#      content: "same" is equal record for record, "changed-content" is the
#      same layout with other values (ids into changed tables, text),
#      "layout-changed" is the same record type with rows added or removed,
#      "record-changed" is a record PAL's type does not hold: the code that
#      reads it multiplies the index by another stride, and the row gives
#      that stride and the field offsets the twin functions' loads and
#      stores map (PAL offset -> offset here). Every member decoded with
#      PAL's type has every pointer inside this ELF's image, every string
#      terminated, every float field finite and no nonzero padding.
# rom_hi is the next start, or the record count times the stride where zero
# fill for the next start's alignment follows. Where the span differs from
# PAL's the row says so and gives both row counts. The USA build is the
# older one (September 2001), and most of its tables hold fewer rows than
# PAL's. Every byte between the two neighbours of each run is claimed by a
# row below or is zero fill of at most 7 bytes: this ELF has no data run
# PAL's table lacks. The member order inside each run is PAL's, with three
# differences the code fixes: motSyncPairs (unmapped_00533FC0) is first in
# its .data run, before item-kind-def; weapon-def is in .rodata, last in the
# first .rodata run; and texture-path is in .rodata, between spider-def and
# way-group, as on the Japanese disc.
