# config/struct_classes.txt -- the layout class of every struct the layout
# asserts touch (tools/gen_layout_asserts.py, port/test/layout_asserts.c,
# docs/port/LAYOUT.md).
#
#   <name> <class> [size=0xNN] [base=0xNN] [pending=<package>] [nosize]  # evidence
#
# class
#   runtime  natural host layout, real pointers: asserted on the 32-bit
#            presets only (the EE layout), free to change on 64-bit
#   overlay  read directly from disc or ELF bytes: frozen on every preset;
#            pointer fields become u32 offsets or are resolved by the loader
#   save     serialised into the save image or the memory card files: frozen
# size=      the struct's size where no header comment gives it
# base=      the header's comments are offsets in an enclosing record, where
#            this struct sits at base
# pending=   a frozen struct whose 64-bit asserts wait for that package to
#            convert its pointer fields. None is pending: the 2C disc-loader
#            structs are converted (docs/port/LOADERS.md), and the ELF tables'
#            records with pointers are `runtime`, decoded field by field into
#            the host layout by the table loader (5B, docs/port/DATA.md).
# nosize     the "N bytes" in the struct's leading comment is not its size
#
# Evidence: "ELF <member>" is a row of config/data_schema.pal.txt (an ELF data
# table, decoded field by field from the user's ELF at boot by
# port/data/tables.c; its EE layout is asserted by the generated
# port/data/gen/table_desc.c on every host for pointer-free records, on a
# 32-bit host for the rest); "R4" is
# docs/research/loader-census.md.
