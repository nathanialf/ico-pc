# config/data_members.jun26.txt -- the ICO Jun-26-2001 demo ELF's data-only ico2000.a members.
#
# One row per (member, section) for the members of config/data_members.pal.txt
# that this ELF holds: 69 of PAL's 72 (the 70th, enemy-def, is committed
# source), and the runs of two members with code, mcdata.o's save icon record
# (mc-icon-sys, below) and EnemyInit.o's 49 enemy-set tables (enemy-model*,
# enemy-set-table, below): 119 members. None of PAL's three unmapped runs has a
# row: hintTable (unmapped_002ADBA0), motSyncPairs (unmapped_00533FC0) and
# jimakuFileName (unmapped_0055FBD0); the demo has none of the three tables
# and no code that reads one, as in the Aug-6-2001 prototype. Each member,
# typed by config/data_schema.jun26.txt, is written as one C translation
# unit by tools/gen_data_c.py (build/jun26/data/<member>.c) from the user's own
# baserom/jun26/baseelf.elf; the bytes are never committed.
#
# Columns: <section> <member> <rom_lo> <rom_hi> <symbol>@<offset>,...
#   section   the section the bytes occupy in the demo ELF
#   rom_lo/hi VMA range [lo, hi) in baserom/jun26/baseelf.elf
#   symbols   the PAL member's names (MAIN.MAP's), offset from rom_lo
#
# Derivation, as for the Aug-6-2001 prototype (that branch's
# config/data_members.aug6.txt): no address comes from a map. Each member's
# base is pinned by the code that reads it: a function the census
# (tools/correlate_elf.py, against the PAL and the aug6 builds) pairs with a
# reader forms the same datum's address with a %hi/%lo pair or a $gp offset in
# both builds. A member no code reads is bounded by its pinned neighbours.
# Each range was then decoded with its record type (config/data_schema.jun26.txt)
# and checked: pointers inside the image, strings terminated, floats finite,
# the row count times the stride reaching the next start or its alignment
# fill. The member order inside each run is the Aug-6-2001 prototype's
# (weapon-def last in the first .rodata run, adpcmfile first in the third,
# texture-path between spider-def and way-group). The demo's .data is about
# 0x81500 bytes larger than PAL's mostly through model-path, whose 1474
# records are 0x14C bytes (PAL 1637 of 0x8C).
# mcdata.o's .data in this build (not an archive member of its own): the
# save icon's icon.sys record, 964 bytes = sizeof sceMcIconSys ("PS2D", the
# title, "summery.ico" as the three icon names, the 512-byte zero tail).
# No word of .text forms its address; it is bounded by mcard.o's McMsgQ
# before it and pad.o's 64-aligned .data after it. PAL reads its icon.sys
# from the disc and has no such record. The name is derived.

# The enemy sets of stage models 02..09 and enemySetTable, the .data that
# follows EnemyInit.o's model 01 (0x4EB318..0x507D00). Not archive members:
# EnemyInit.o's own tables, which PAL's EnemyInit.c defines in C for model 01
# alone (its enemySetTable has one row; the demo's enemy_Initialize runs to
# 9). Carved here so their values are read from the base ELF at build time,
# one row per run of one record type, in the ELF's order; the members follow
# EnemyInit.c in the link order. Each base is pinned by the pointer that
# names it: enemySetTable (enemy_Initialize's lui/addiu of 0x507CB8) points
# at each model's set list, each list at its sets ({kinds, kindNum, pos,
# posNum}), each set at its kind records ({list, kind}) and position table,
# each record at its -1-closed list. A row ends where its records end; the
# 4-byte fill after a one-set list and the 8 bytes before a 16-aligned
# position table lie between rows (the next member's alignment). Every name
# is derived: model NN is enemySetTable's row NN-1 (row 0 is PAL's
# enemymodel01), a second set takes a 'b'; KindK is the list of enemy kind K.
