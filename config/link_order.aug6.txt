# config/link_order.aug6.txt: the objects of the Aug-6-2001 prototype link, one per line, in link order.
#
# The prototype disc ships a MAIN.MAP, but it is the PAL disc's file byte for
# byte and describes that later link, not this ELF. This order is PAL's
# (config/link_order.pal.txt on main, MAIN.MAP's object order) carried over by
# the function census, tools/correlate_elf.py: each PAL object keeps its place
# while its .text twins in the aug6 ELF keep the same relative order. The
# disc's TRFILE.TXT (an address, function, source file and line per source
# line) is of a build close to this one: its addresses differ from
# this ELF's by an offset that is constant between neighbouring functions, and
# shifted by that offset it gives the census's own name to 3299 of 3334 twins
# it covers, so it is used below as evidence of where an object's functions
# are. A line that departs from PAL's order says why in a comment on the line.
# Every output section of config/link.aug6.ld takes its inputs in this one
# order. tools/gen_ninja.py reads this file and fails on any tracked .c/.s/.dsm
# under ico2/ or sce/ that is missing here, and on any listed file that does
# not exist. tools/ico_version.{py,sh} detect the target (aug6) by this file's
# existence.
#
# Line forms:
#   <path>             a source file (.c compiled by tools/compile_c.sh, .s
#                      assembled per archive, ico2/vusrc/*.dsm by dvp-as)
#   data:<member>      a data-only ico2000.a member: every row of
#                      config/data_members.aug6.txt for it, generated from the
#                      user's base ELF at build time by tools/gen_data_c.py from
#                      the record types config/data_schema.aug6.txt names. The
#                      data: lines are PAL's members in the places
#                      config/data_members.aug6.txt finds them: PAL's three
#                      unmapped runs are absent, weapon-def and texture-path
#                      are in .rodata (PAL's .data), adpcmfile moves inside
#                      .rodata, and the three lines say where.
#
# Tokens after a path:
#   align.<sec>=16     the ROM starts this object's <sec> (data or rodata)
#                      16-aligned after fill that its own section alignment
#                      does not produce. While any line carries one,
#                      tools/gen_ninja.py lists that output section input by
#                      input (build/<sec>.inputs.ld, which the script
#                      INCLUDEs) with an ALIGN before the object; otherwise
#                      the file is empty and the script's wildcards alone
#                      place the section. Each token below was measured on
#                      the aug6 ELF, and its comment gives the aug6 addresses
#                      and the fill before it.
#   overlay-fill=N     on a .dsm line: the byte, decimal 0 to 255, that
#                      dvp-as repeats over the program's constant-address
#                      overlay section (--overlay-fill=N, from
#                      tools/binutils-dvp-overlay-fill.patch). It is the
#                      period assembler's uninitialised heap memory, measured
#                      on the disc's ELF, not a feature of the source. The
#                      aug6 ELF holds 0x6E (110) in all five, as the JPN and
#                      USA ELFs do, where PAL's are zero; the seven
#                      continuation overlays are zero in all four.
#
# No object owns these zero runs at the section boundaries (ROM offsets, VMA
# minus 0x100000, from the aug6 ELF's section headers): 0x170A50, the 48 bytes
# after .vutext (.reginfo is not allocated, the gap is fill); 0x44D978, past
# the end of .data; 0x52BA38, past the end of .lit4. Every other run of fill
# inside a section is reproduced by the next object's own alignment or a token
# below.
#
# The aug6 build is the earliest of the four: 1561 of PAL's 5755 functions
# have no twin in it and 1209 of its functions have none in PAL. The census
# marks 16 PAL objects absent (no function with a twin). Each was looked for in
# the aug6 ELF by its PAL object's .data, .rodata, .sdata and .lit4 with every
# relocated field masked, by TRFILE.TXT's functions for its source file shifted
# to this ELF, and by the sizes and order of the aug6 functions no PAL function
# claims, where its link order puts it:
#   present, in an earlier form (the line carries a comment saying why):
#     act-wish.c, attackhit.c, mail-add-data.c, flag.c, girlForceField.c,
#     handManager.c, st04e.c, st05e.c, st13a.c, st19a.c, st24a.c.
#   absent: puddle.c, waterDot.c, windmill.c, sce/libcdvd/libcdvd_267388.c and
#     sce/libscf/libscf.c. Their sources and lines are not on this branch:
#     puddle.c sits where particleLayout.c's last function (0x1E6190,
#     ParticleLayoutDL by TRFILE.TXT) meets rope.c's first, waterDot.c where
#     TRFILE.TXT gives the functions between torch.c's last twin and
#     waySystemManager.c's first to torch.c, windmill.c where windManager.c's
#     last twin meets wireLetter.c's first, libcdvd_267388.c where cdvd015.c's
#     twin meets cdvd047.c's first (0x249D48), and libscf.c where ipuinit.c's
#     last twin meets sound.c's first; TRFILE.TXT names none of the three game
#     sources, and no object's .text, .data, .rodata, .sdata or .lit4 is in the
#     ELF.
#
# Departures from PAL's order:
#   ico2/fumi/sound/adpcm_init.c sits between ico2/fumi/isys/gobj_cam_dl.c and
#   ico2/fumi/src/act-env.c, not between obj_manager.c and s_init.c: its 22
#   twins lie in the aug6 .text at 0x1F92A0..0x1FA070, after gobj_cam_dl.c's
#   last twin and before act-env.c's first, TRFILE.TXT gives the function
#   before them (0x1F9188) to adpcm_init.c, and its PAL .sdata is at 0x62D9A0,
#   after DisplayFont.c's at 0x62D960, not beside s_init.c's at 0x62C368.
#   ico2/omori/src/lws_kyomi.c sits between ico2/omori/src/access.c and
#   ico2/omori/src/objact.c, not between hand-camera.c and mail-add-data.c:
#   its one twin, SetParamKyomiGObj, lies in the aug6 .text between access.c's
#   last twin and objact.c's first, as in the USA build.
