# config/link_order.pal.txt: the objects of the PAL link, one per line, in link order.
#
# The order is the retail link's object order as MAIN.MAP gives it: every
# output section of config/link.pal.ld takes its inputs in this one order.
# Each object with no .text and each data-only member sits where its other
# sections and MAIN.MAP's member order put it; the five VU microprograms are
# listed as their sources. tools/gen_ninja.py reads this file and fails on any
# tracked .c/.s/.dsm under ico2/ or sce/ that is missing here, and on any
# listed file that does not exist. tools/ico_version.{py,sh} detect the
# target (pal) by this file's existence.
#
# Line forms:
#   <path>             a source file (.c; in the PS2 build .s assembled per
#                      archive and ico2/vusrc/*.dsm by dvp-as)
#   data:<member>      a data-only ico2000.a member: every row of
#                      config/data_members.pal.txt for it, generated from the
#                      user's base ELF at build time by tools/gen_data_c.py from
#                      the record types config/data_schema.pal.txt names. Inside each
#                      run of them the order is MAIN.MAP's: its sections keep
#                      their ROM order and interleave by member name.
#
# Token after a path:
#   align.<sec>=16     the ROM starts this object's <sec> (data or rodata)
#                      16-aligned after fill that its own section alignment
#                      does not produce. While any line carries one,
#                      tools/gen_ninja.py lists that output section input by
#                      input (build/<sec>.inputs.ld, which the script
#                      INCLUDEs) with an ALIGN before the object; otherwise
#                      the file is empty and the script's wildcards alone
#                      place the section.
#
# No object owns these zero runs (ROM offsets, VMA minus 0x100000): 0x18ECB0,
# the 80 bytes after .vutext (.reginfo is not allocated, the gap is fill);
# 0x44D320, past the end of .data; 0x539C54, past the end of .lit4; and eight
# pads that the next object's own section alignment reproduces (0x44A3CC in
# .data; 0x44DB0C, 0x51EEC2, 0x51F182, 0x51F218, 0x51FA18 and 0x51FBD8 in
# .rodata; 0x53B8D9 in .sdata). The run at 0x538848 in .rodata is empty.
